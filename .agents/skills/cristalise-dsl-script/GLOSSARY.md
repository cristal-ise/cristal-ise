# Glossary — CRISTAL-iSE Script DSL

The domain model for CRISTAL-iSE Script DSL. **Bold terms** in any definition are themselves defined in this glossary; find them by their heading.

## Core Concepts

### Script

A **Description Item** that encapsulates executable code using **JSR-223 API** that can be associated with **Activities** or execute as GET endpoints. Scripts are the primary mechanism for implementing custom business logic in CRISTAL-iSE.

_Avoid_: Code, Function, Procedure, Macro

### Script DSL

The **Domain Specific Language** for defining **Script** resources in CRISTAL-iSE using Groovy syntax. The Script DSL provides a declarative way to define script parameters, file references, and dependencies.

_Avoid_: Script Language, Script Syntax

### JSR-223 API

The Java Scripting API (JSR-223) that enables CRISTAL-iSE to support multiple scripting languages including Groovy (primary), JavaScript, and Jython. This API provides a standardized way to execute scripts in different languages.

_Avoid_: Scripting Engine, Script API

## DSL Components

### ScriptDelegate

The **Groovy class** that implements the **Script DSL** methods and generates the underlying XML representation. ScriptDelegate uses **MarkupBuilder** to create cristalscript XML and provides methods like `script()`, `input()`, `output()`, and `include()`.

_Avoid_: Script Builder, DSL Processor

### MarkupBuilder

A Groovy utility class used by **ScriptDelegate** to generate XML content. In the context of Script DSL, it's used to create the cristalscript XML structure that gets embedded as CDATA.

_Avoid_: XML Builder, XML Generator

### cristalscript

The root XML element generated by the **Script DSL**. Contains script definitions, includes, inputs, outputs, and the actual script content.

_Avoid_: Script XML, Script Definition XML

## File and Path Concepts

### moduleDir

A **binding variable** that provides the base directory path of the current module. Used to create **portable file references** in script definitions. Always use `moduleDir` instead of absolute paths.

_Avoid_: Module Path, Base Directory

### File Reference

The approach used by **Script DSL** to reference external script files containing the actual executable code. File references use the `script('language', 'filePath')` syntax and support relative paths with `moduleDir`.

_Avoid_: Script Path, External Reference

### Portable File Reference

A **file reference** that uses `moduleDir` and relative paths, making the script definition work across different environments and deployment scenarios.

_Avoid_: Relative Path, Environment-Independent Path

## Parameters and Contracts

### Input

A parameter declaration in **Script DSL** that defines a variable that will be available to the script during execution. Inputs are declared with `input(String name, String type)`.

_Avoid_: Parameter, Argument, Input Parameter

### Output

A parameter declaration in **Script DSL** that defines a variable that the script will produce and make available to the calling context. Outputs are declared with `output(String name, String type)` or `output(String type)`.

_Avoid_: Return Value, Result, Output Parameter

### Parameter Contract

The agreement between a **Script** definition and its actual script code, specifying what inputs are available and what outputs must be produced. The contract ensures type safety and documentation of the script's interface.

_Avoid_: Interface, Signature, API Contract

### param

An alias method in **Script DSL** for `input()`. Both methods serve the same purpose of declaring input parameters for a script.

_Avoid_: Parameter Method, Input Method

## Binding Variables

### Binding

The mechanism by which variables are made available to scripts during execution. **Binding variables** like `item`, `agent`, and `job` are automatically provided based on the script's execution context.

_Avoid_: Variable Binding, Context Variables

### item

A **binding variable** of type `org.cristalise.kernel.entity.proxy.ItemProxy` that represents the current **Item** being processed. Available to most scripts, especially those linked to **Activities**.

_Avoid_: Current Item, Target Item

### agent

A **binding variable** of type `org.cristalise.kernel.entity.proxy.AgentProxy` that represents the **Agent** executing the script. Available to **Activity-linked scripts**.

_Avoid_: User, Executing Agent

### job

A **binding variable** of type `org.cristalise.kernel.entity.Job` that represents the **Job** context. Available to **Activity-linked scripts** and provides access to job outcomes, schema, and properties.

_Avoid_: Execution Context, Job Context

## Dependencies and Reuse

### include

A **Script DSL** method that declares a dependency on another **Script** resource. Including scripts enables code reuse and modular design. Syntax: `include(String name, Integer version)` or `include(Script script)`.

_Avoid_: Import, Depend, Use

### Script Inclusion

The practice of using `include()` to reference other **Scripts** within a **Script** definition. This enables modular script design, code reuse, and dependency management.

_Avoid_: Script Import, Script Dependency

### Included Script

A **Script** that is referenced by another script via the `include()` method. Included scripts become available in the execution context and can provide utility functions, validation logic, or other reusable functionality.

_Avoid_: Imported Script, Dependent Script

## Error Handling

### ErrorInfo

The primary error handling class in CRISTAL-iSE scripts: `org.cristalise.kernel.scripting.ErrorInfo`. Used to report errors from script execution with optional message, details, and cause information.

_Avoid_: Error Object, Exception, Script Error

### errors

A conventional **output parameter** name used for error reporting in **Script DSL**. Most scripts should include `output('errors', 'org.cristalise.kernel.scripting.ErrorInfo')` to handle error conditions consistently.

_Avoid_: error, scriptError, exception

## Language Support

### Groovy

The **primary recommended language** for CRISTAL-iSE scripts. Groovy provides full integration with CRISTAL-iSE Java APIs, better IDE support, rich type system, and mature ecosystem.

_Avoid_: Groovy Script, Groovy Language

### JavaScript

A scripting language supported via **JSR-223 API**. Useful for simple expressions, web-related scripting, and JSON processing in CRISTAL-iSE scripts.

_Avoid_: JS, ECMAScript

### Jython

Python implementation supported via **JSR-223 API**. Jython enables Python-based logic, integration with Python libraries, and data science applications in CRISTAL-iSE scripts.

_Avoid_: Python, Python Script

## Standard Script Types

### Aggregate Script

A **Script** type that generates aggregated XML data from an **Item**. Typically follows the naming pattern `ItemName_Aggregate`.

_Avoid_: Aggregation Script, Data Aggregator

### Query List Script

A **Script** type that queries and returns collections of data, typically as a Map. Usually follows the naming pattern `ItemName_QueryList`.

_Avoid_: Query Script, List Script

### Update Script

A **Script** type that implements update logic for **Items**. Common examples include `CrudEntity_ChangeName` and other property modification scripts.

_Avoid_: Modify Script, Change Script

### Validation Script

A **Script** type that performs validation logic on input data, **Item** state, or business rules. Typically produces validation errors as output.

_Avoid_: Validator, Validation Function

## Templates and Generation

### MVEL2 Template

The `dev` module uses MVEL2 files to scaffold Items with CRUD functionality. There are 2 template files to generate 2 Scripts. Use them when creating CRUD Items.

Aggregrate Script: `dev/src/main/resources/templates/item_aggregate_groovy.tmpl`
Query List Script: `dev/src/main/resources/templates/item_queryList_groovy.tmpl`

**MVEL2 template syntax** use variables like `@{item.name}`, `@{version}`, and `@{itemPackage}` to generate context-specific code.

_Avoid_: Code Template, Generation Template

## Execution Contexts

### Activity-Linked Script

A **Script** that is associated with an **Activity** via the `Script($scriptVar)` or `Script(scriptName, scriptVersion)` syntax in **Activity DSL**. Activity-linked scripts receive the full set of **binding variables** (`item`, `agent`, `job`).

_Avoid_: Activity Script, Bound Script

### Standalone Script

A **Script** that executes as a GET endpoint or is called directly, rather than being linked to an **Activity**. Standalone scripts only have access to their declared **input** parameters.

_Avoid_: Independent Script, Endpoint Script

### Workflow Routing Script


### GET Endpoint

An execution context where **Scripts** can be exposed as HTTP GET endpoints. GET endpoint scripts launched in read transaction to perform query operations to collect and potentially convert data and return it without modifying system state.

_Avoid_: REST Endpoint, Web Service, API Endpoint
